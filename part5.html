01

The lineup — eight models, one release

Qwen3 shipped six dense models and two mixture-of-experts models simultaneously, all under Apache 2.0, all sharing one pre-training corpus and one tokenizer. This is the release that made Qwen the default open family outright.

The one to notice

Qwen3-30B-A3B was the release's quiet triumph. Roughly 60GB of BF16 weights — or about 18GB at 4-bit, so a single 24GB card — while doing the arithmetic of a 3B model per token. It made "large model quality at small model speed" a thing an individual could actually run, and its successors (30B-A3B-2507, Qwen3.5-35B-A3B, Qwen3.6-35B-A3B) have been the family's most-deployed models ever since.

02

The architecture, precisely

Qwen3's backbone is a conventional pre-norm decoder — GQA, SwiGLU, RoPE, RMSNorm — with two deliberate changes from Qwen2 that are both about training stability at scale.

Removed: QKV bias

Qwen 1.0 kept bias terms on the QKV projection because they helped context extrapolation. By Qwen3 the long-context capability was trained rather than extrapolated, so the bias no longer earned its place — and biases are a known source of activation outliers, which hurt both training stability and post-training quantisation.

Added: QK-Norm

RMSNorm applied to the query and key vectors before the attention dot product. Attention logits are the product of two learned vectors and their magnitude can grow without bound during training, causing loss spikes at scale. Normalising Q and K bounds the logit magnitude directly, which is why deep MoE models like the 94-layer 235B can be trained without babysitting.

03

Inside the MoE block

Qwen3's mixture-of-experts made one notable break from Qwen2's: it dropped shared experts entirely. Qwen1.5-MoE and Qwen2-57B-A14B both used always-on shared experts to hold common knowledge; Qwen3 uses 128 routed experts, 8 activated, and nothing always-on.

A global-batch load-balancing loss keeps the router from collapsing onto a few favourite experts. Without it, MoE training reliably degenerates: a handful of experts get all the traffic, the rest never learn, and you have paid for 128 experts to get the capability of six.

04

Three pre-training stages, 36 trillion tokens

Qwen3 was trained on roughly 36 trillion tokens across 119 languages and dialects — double Qwen2.5's corpus, and roughly five times Qwen2's. The curriculum is staged, and each stage has a distinct job.

The data flywheel

Two details in the corpus construction are worth borrowing. First, Qwen2.5-VL was used to extract text from documents and PDFs, opening a corpus that pure text crawling cannot reach. Second, Qwen2.5-Math and Qwen2.5-Coder generated synthetic textbooks, problems and code for the reasoning stage. Each generation is used to build the next generation's data — a compounding advantage that is difficult for a new entrant to replicate, and arguably a larger moat than any architectural choice in the model.

05

Hybrid thinking — the idea and the controls

Qwen3's headline feature: one checkpoint, two modes. Thinking mode emits a <think> trace before answering; non-thinking mode answers immediately. Both live in the same weights, and the mode is selected per request.

The three controls, in practice
# 1. Per-request, via the chat template kwargs (vLLM / SGLang OpenAI API)
{
  "model": "Qwen/Qwen3-32B",
  "messages": [...],
  "chat_template_kwargs": { "enable_thinking": false }
}

# 2. Soft switch inside the conversation — the user (or your scaffold) can flip mid-dialogue
"Refactor this function. /no_think"
"Now prove the loop terminates. /think"

# 3. Server-wide default: ship a chat template with thinking off
vllm serve Qwen/Qwen3-32B --chat-template ./qwen3_nonthinking.jinja
#    or, on current vLLM:
vllm serve Qwen/Qwen3-32B --default-chat-template-kwargs '{"enable_thinking": false}'
Why this was ambitious

Thinking and non-thinking are not just different output lengths — they are different policies. One is trained to explore, backtrack and doubt; the other to commit immediately. Asking one parameter set to hold both, and to switch cleanly on a token in the prompt, is a genuinely hard post-training problem. Stage 3 of the pipeline exists solely to solve it.

06

Four post-training stages, and distillation for the small models

The flagship models went through a four-stage pipeline. The six smaller models did not — they were distilled from the flagships, which is both cheaper and, per the technical report, better than running the full pipeline at small scale.

07

Agentic capability and MCP

Qwen3 was the first generation post-trained for tool use as a first-class objective rather than a formatting exercise, and the first with explicit Model Context Protocol support in the reference agent framework.

Qwen-Agent — the reference tool-calling loop, with MCP servers
from qwen_agent.agents import Assistant

llm_cfg = {
    'model': 'Qwen3-32B',
    'model_server': 'http://localhost:8000/v1',   # any OpenAI-compatible endpoint
    'api_key': 'EMPTY',
}

tools = [
    {'mcpServers': {
        'time':  {'command': 'uvx', 'args': ['mcp-server-time']},
        'fetch': {'command': 'uvx', 'args': ['mcp-server-fetch']},
    }},
    'code_interpreter',                          # a built-in tool
]

bot = Assistant(llm=llm_cfg, function_list=tools)
for chunk in bot.run(messages=[{'role': 'user', 'content': 'Summarise https://qwenlm.github.io/blog/qwen3/'}]):
    print(chunk)

What "trained for agents" actually means

  • Schema adherence under pressure. Emitting valid JSON arguments for a tool is easy in isolation and hard after 8,000 tokens of reasoning. Stage 4 RL rewards it directly.
  • Recovery from tool errors. A tool returns a stack trace; the model must diagnose and retry with different arguments rather than repeating the same call or giving up.
  • Knowing when not to call. Over-eager tool use is as damaging as under-use — a model that searches the web to answer "what is 2+2" is unusable at scale.
  • Multi-turn state. Holding a plan across a dozen tool round-trips without losing the thread, which is where the interaction with thinking mode gets subtle: the trace helps planning but consumes the context the plan needs.
Serving note

Qwen3's tool-call format is Hermes-style. In vLLM that means --enable-auto-tool-choice --tool-call-parser hermes. The Coder line uses a different, XML-flavoured format with its own parser — getting this pairing wrong produces tool calls that appear in the text content and are never dispatched. Part 11 has the full matrix.

08

The 2507 split — admitting the experiment failed

In July 2025, three months after launch, the team published Qwen3-235B-A22B-Instruct-2507 and Qwen3-235B-A22B-Thinking-2507 as separate models, with matching 30B-A3B variants. The Instruct model's card states it plainly: it supports only non-thinking mode, and enable_thinking=False is no longer needed because there is no longer anything to disable.

Why it did not hold together

  • The modes compete for capacity. Post-training a single parameter set toward two contradictory policies means each is a compromise. The 2507 models are visibly stronger in their respective lanes.
  • Mode leakage. In practice the hybrid would sometimes produce short, thinking-flavoured hedging in non-thinking mode, or skip real deliberation in thinking mode — a blurred boundary rather than a clean switch.
  • Evaluation ambiguity. Every benchmark result needed a mode annotation, and comparisons across labs became muddled.
  • Serving reality. Most deployments picked one mode at the gateway and never changed it, so the flexibility was paying a quality cost for a feature nobody used.

The 2507 refresh also doubled native context to 262,144 tokens and improved instruction following, tool use, and long-context comprehension across the board. If you run any Qwen3 flagship today, run a 2507 checkpoint — the original April weights are strictly superseded.

The idea was not wrong, the implementation was early

Qwen3.5 revisits exactly this problem and, per Alibaba, gets it right: reasoning and non-reasoning modes in a single model without the quality tax, alongside native multimodality. Part 09 examines what changed — and the honest answer involves a much larger model, a different architecture, and a year of post-training research.

09

Serving Qwen3: the flags that matter

vLLM — the four configurations you will actually use
# 1. Dense, single GPU, thinking enabled, traces split into reasoning_content
vllm serve Qwen/Qwen3-8B \
  --reasoning-parser qwen3 \
  --max-model-len 32768

# 2. Same model as a tool-calling agent backend
vllm serve Qwen/Qwen3-8B \
  --enable-auto-tool-choice --tool-call-parser hermes \
  --reasoning-parser qwen3

# 3. MoE across 4 GPUs with expert parallelism — usually better than pure TP for sparse MoE
vllm serve Qwen/Qwen3-30B-A3B-Instruct-2507 \
  --tensor-parallel-size 4 --enable-expert-parallel \
  --max-model-len 262144

# 4. 128K context on a model whose native window is 32K — YaRN, applied explicitly
vllm serve Qwen/Qwen3-8B \
  --rope-scaling '{"rope_type":"yarn","factor":4.0,"original_max_position_embeddings":32768}' \
  --max-model-len 131072

Sampling

Thinking mode: temperature 0.6, top_p 0.95, top_k 20. Non-thinking mode: temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5 if you see repetition. Never greedy decoding in thinking mode — see Part 04.
